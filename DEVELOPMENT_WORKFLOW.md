# 🛠️ CodeAtlas Incremental Feature Workflow

This guide establishes the mandatory protocol for adding new features to **CodeAtlas** one by one.
Adhering to this process ensures the codebase remains robust, maintainable, and completely navigable as it scales.

---

## 🔁 The 6-Step Feature Implementation Loop

Whenever you are tasked with implementing a new feature, follow these 6 sequential steps:

### Step 1: Register in `FEATURE_TRACKER.md`
- Assign a unique Feature ID: `FEAT-001`, `FEAT-002`, etc.
- Set status to `[IN_PROGRESS]`.
- Identify the target files and state requirements before writing code.

### Step 2: Consult `CODEBASE_MAP.md`
- **DO NOT** read all files in the project.
- Use the **Fast Task Router** in `CODEBASE_MAP.md` to identify the 1 to 3 files that need modification.
- Read only those specific files or line ranges.

### Step 3: Implement Clean, Production-Ready Code
- Write strongly-typed, complete code (Python type hints, TypeScript interfaces).
- **Zero TODOs or placeholders**: Never commit stubbed or fake logic.
- Follow established patterns:
  - If adding backend routes: update `backend/app/main.py` and `backend/app/models/schemas.py`.
  - If adding frontend components: use Tailwind CSS dark palette (`zinc-950`, `zinc-900`, `zinc-800`), Lucide icons, and register types in `frontend/src/types/index.ts`.

### Step 4: Verification & Automated Tests
- For backend changes: run targeted pytest:
  ```pwsh
  backend\.venv\Scripts\pytest backend/tests/test_target.py -v
  ```
- For frontend changes: verify TypeScript build:
  ```pwsh
  frontend\node_modules\.bin\tsc.cmd -p frontend\tsconfig.json --noEmit
  ```
- If a new feature introduces new logic, write a corresponding unit test in `backend/tests/`.

### Step 5: Update Documentation & Status
- Update `CODEBASE_MAP.md` if any new endpoint, component, or service was created.
- Update `FEATURE_TRACKER.md`: mark feature as `[COMPLETED]`, record test commands and notes.

### Step 6: Atomic Git Commit
- Stage only the relevant files:
  ```pwsh
  git add <modified_files>
  ```
- Create a semantic commit message:
  ```pwsh
  git commit -m "feat(scope): concise description of new feature"
  ```
- Provide the user with exact instructions and verification commands.

## 🛡️ Coding & Architectural Standards

1. **Monorepo Separation:**
   - Backend logic stays strictly in `/backend`.
   - Frontend logic stays strictly in `/frontend`.
   - Never import frontend files into backend or vice versa.

2. **UI Palette Constraints:**
   - Backgrounds: `bg-zinc-950` / `bg-zinc-900`.
   - Borders: `border-zinc-800` / `border-zinc-700`.
   - Text: `text-zinc-100` (primary), `text-zinc-400` (muted).
   - Accents: Sky (`#38bdf8`), Emerald (`#34d399`), Amber (`#fbbf24`), Purple (`#c084fc`).

3. **Citations Format:**
   - All code citations generated by AI or backend services must strictly use the format:
     `[file_path:start_line-end_line]` (e.g. `[src/components/App.tsx:12-45]`).
